# Kanbanity

Адаптивная Kanban-доска с Node.js API и базой SQLite. Задачи, проекты, настройки рабочего пространства, прочитанные уведомления и история действий сохраняются в файл базы данных.

## Запуск

Требуется Node.js 22.13 или новее (используется встроенный модуль `node:sqlite`).

```bash
npm install
npm run dev
```

Откройте адрес Vite, показанный в терминале. Команда `npm run dev` запускает API и Vite вместе. API по умолчанию слушает `127.0.0.1:3001`, а интерфейс проксирует запросы `/api` к нему.

Данные сохраняются в `data/kanbanity.sqlite`. Чтобы указать другой файл базы данных:

```powershell
$env:DATABASE_PATH = "C:\путь\к\kanbanity.sqlite"
npm run dev
```

Для production:

```bash
npm run build
npm start
```

Production-сервер раздаёт собранный интерфейс и API на `http://127.0.0.1:3001`. Порт и адрес сервера настраиваются переменными `PORT` и `HOST`.

Проверки:

```bash
npm test
npm run build
```

## Возможности

- Канбан-колонки и представления «Доска», «Список» и «Активность».
- Одна общая кнопка создания задачи; колонку и остальные поля можно выбрать в форме.
- Навигация по обзору, каталогу проектов и команде; три независимые доски проектов.
- Настройки названия и описания рабочего пространства с сохранением в SQLite.
- Создание, редактирование и удаление задач: описание, исполнитель, приоритет, срок, метки и комментарии.
- Перемещение задач перетаскиванием; WIP-лимиты блокируют перенос в переполненную колонку.
- Создание, переименование и удаление пустых колонок, настройка WIP-лимита.
- Поиск по задачам, фильтрация по приоритету, исполнителю и меткам.
- Сортировка доски и списка по номеру задачи, приоритету, сроку или названию в обоих направлениях.
- История изменений, счётчик выполнения проекта и адаптивная раскладка.

## Ограничения текущей версии

SQLite/API сейчас хранит единый снимок состояния прототипа в локальной таблице `app_state`; это локальная база, а не многопользовательский production-сервис. Регистрация и JWT, роли и серверная авторизация, отдельные таблицы сущностей и миграции, вложения, OpenAPI и CI/CD пока не реализованы. При первом запуске ранее сохранённое состояние из `localStorage` переносится в SQLite. Значение WIP-лимита и названия колонок можно изменить через меню `⋯` колонки; колонку с задачами удалить нельзя.

## Проверка

Vitest и React Testing Library проверяют пользовательские сценарии через тестовый API; Node.js test runner проверяет SQLite API, валидацию и сохранение данных после перезапуска сервера. `npm run build` выполняет строгую проверку TypeScript и production-сборку.
